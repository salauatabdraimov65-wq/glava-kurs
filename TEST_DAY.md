# Тестовый день: порядок действий

Код заморожен тегом `freeze`. **Код не меняем.** Любая правка результата — только через `glava.edit` (журнал + отдельный коммит). Цель — не больше 30 человеко-минут правок на главу.

Всё ниже проверено репетициями на незнакомых текстах (`samples/rehearsals/README.md`): незнакомые страницы обучающих книг, английский текст, бурение с `--domain drilling`.

## 0. До выдачи теста
```
git checkout main && git pull && git log -1 --oneline     # на теге freeze
uv sync
uv run python -m glava.llm                                # расход по журналу этого компьютера
uv run python -m glava.check --all                        # всё зелёное на обучении и контроле
```
- Остаток денег смотреть в кабинете OpenAI: журнал считает только свой компьютер. Стоп-кран — `LLM_BUDGET_USD` в `.env`.
- Ключ в `.env` у того, кто гоняет главы. Два компьютера могут гонять главы параллельно.

## 1. Что выдадут
- главы-двойники (другие авторы, возможно английский);
- глава-сдвиг (другой домен нефтегаза, скорее всего бурение);
- узел для ролика (назначат организаторы);
- пакет с закладками (`package.json` + кадры) без ключа.

Положить главы в `../test/`. Для каждой открыть md и найти:
- первую и последнюю метку `<!-- page N -->` главы;
- если на первой или последней странице есть куски соседних разделов — начало заголовка главы (`--start-at`) и заголовок следующего раздела (`--end-at`).

## 2. Прогон главы — одна команда
Организаторам по главам нужны слой, маршрутизация и курс; роликов всего два — на объявленные темы (шаг 3).
Поэтому главы гоняем **без ролика** (`--no-video`), а ролики делаем отдельно:
```
uv run python -m glava.pipeline test_1 --md ../test/<файл>.md --pages <N1>-<N2> --no-video \
    --title "Автор. Название главы" [--start-at "<начало заголовка>"] [--end-at "<следующий раздел>"]
uv run python -m glava.check test_1
```
**Четыре главы — параллельно**, каждая в своём окне терминала (test_1, test_2, test_3, shift_1): ≈5 минут на всё,
вызовы модели и кэш общие. В конце: `uv run python -m glava.metrics` и `uv run python -m glava.report`.

| Случай | Флаг |
|---|---|
| английская глава | `--lang en` |
| сдвиг (бурение) | `--domain drilling` (пакет `domain/drilling/` уже готов, см. шаг 4) |
| денег мало | `--no-review` (без самопроверки модулем проверки) |
| ролик соберём отдельно на назначенный узел | `--no-video` |

Этапы: слой → полнота по идеям (+ добор) → самопроверка (+ исправления) → схемы и графики по формулам → сценарий → ролик → курс.

| | С роликом | `--no-video` | `--no-review --no-video` |
|---|---|---|---|
| Время | 7–8 мин (ролик 2–10 мин) | ≈4–5 мин | ≈3 мин |
| Деньги | ≈$0.5–1.0 | ≈$0.5–1.0 | ≈$0.3–0.4 |

**Упал этап** — перезапуск с него: `--from <этап>` (`layer, recall, review, illustrate, scene, video, course`). Сбой ролика конвейер не останавливает: курс собирается, а шаг закрывают текст и схема.

## 3. Два ролика на объявленные темы
Найти шаг по теме (без модели, мгновенно) — команда сама подскажет строку для ролика:
```
uv run python -m glava.find --test "тема ролика из объявления"      # ищет сразу по всем главам теста
```
Затем (для каждой темы своя команда; уже собранный ролик не перерендеривается):
```
uv run python -m glava.pipeline test_1 --from scene --video-node <node_id> [--video-format short|long]
```
- Шаблон сцены выбирается по типу трудности узла: И/Пр → `well_tool_curve`, Ф/Н → `pressure_diffusion`, М/В/П/Р → `section_through_time`.
- `--from scene` пересобирает и курс, ролик встраивается в шаг.
- Посмотреть ролик со звуком и без. Ошибка в факте → правка `layer.json` + `glava.edit` + `--from illustrate`.
- mp4 в `.gitignore` — в сдачу класть явно: `git add -f runs/test_1/video/*/video*.mp4`.

## 4. Сдвиг: доменный пакет (время записывается само)
- **Домен — бурение:** пакет `domain/drilling/` готов, прогон с `--domain drilling`.
- **Домен другой** (добыча, транспорт, переработка…): прогон с `--domain <новое_имя>` (латиницей, например `production`).
  Папки нет — конвейер сам соберёт черновик пакета из главы (`layer.domain_new`, ≈15 с): оформление и общие пункты —
  из геологии, обозначения, заблуждения, произношение, масштабы и чек-лист — по тексту главы (обозначения и числа
  проверяются по тексту). Время сборки записано в `domain/<имя>/README.md`.
- Затем: просмотреть `domain/<имя>/*.md|json` (5–10 мин), лишнее убрать — время проверки вписать в README пакета
  и в `manual_edits.csv`; `uv run python -m layer.domain_pack <имя>` (глоссарий и мосты в ИТ из слоя).

## 5. Пакет с закладками
```
uv run python -m review.run ../test/package.json --chapter-md ../test/<глава>.md -o review/out/answer_test.json
```
≈1 мин и ≈$0.2 на пакет из 80–90 целей. Ответ всегда создаётся и проходит схему. Подробно — `review/RESULTS.md`, раздел «На тесте».

## 6. Ручные правки — только так
```
uv run python -m glava.edit --chapter test_1 --file runs/test_1/layer.json --what "что исправлено" \
    --minutes 6 --people 1 --run 1 --why "почему"
uv run python -m glava.pipeline test_1 --from illustrate      # пересобрать зависящее
```
Правим только явные ошибки фактов. Не «улучшаем» текст.

## 7. Сдача к 14:00
```
git add runs/ manual_edits.csv metrics.csv domain/ config/chapters.json review/out/
git add -f runs/*/video/*/video*.mp4
git commit -m "Тест: ..." && git push
```
Тег `test-submit`. Проверить, что курс каждой главы открывается двойным кликом (`runs/<id>/course/index.html`).

Для защиты (6 минут показа «что конвейер сделал сам»): `uv run python -m glava.report` → `runs/REPORT.html` —
по каждой главе теста время, деньги, проверки ТЗ, ручные правки и ссылки на курсы и ролики.

## 8. Пересборка на защите (1–2 минуты)
Изменить одно число в учебном слое и показать его на странице курса — одна команда, курс пересобирается за секунды:
```
uv run python -m glava.set_text latyshova_gl5_par17-20 "4–8 см³/ч" "5–9 см³/ч"
open runs/latyshova_gl5_par17-20/course/index.html          # шаг 3 «Водоотдача и давление раствора»
```
Полная пересборка (схемы, графики, сценарий, ролик, курс) — то же с `--full` (≈4 мин). После показа вернуть: `git checkout runs/latyshova_gl5_par17-20 metrics.csv`.
Можно на любой тестовой главе: взять число из текста шага и подставить в команду.
