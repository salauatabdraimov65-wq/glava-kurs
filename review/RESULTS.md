## Как получен

Бесплатные проверки кодом + `bulk` + `strong` (независимо), замечание остаётся при ≥ 2 сигналах, затем обратная проверка «найди дословное подтверждение», потолок 20. Подробности — `review/screen.py`, `review/run.py`.

## Честные оговорки

- Оценка сделана один раз; порог и промпты по результату не подгонялись (пакет один, тест — на незнакомых главах).
- Часть ключа попала в поле зрения агента через скриншот человека (запись по C006) и через строку «Пропущены» в выводе скрипта. Список пропущенных целей агент **не использовал** для правок и сюда не переносит; для чистоты оценки учитывать это при сравнении с другими прогонами.
- Английская глава проверена только на синтетическом пакете из 5 элементов.
- Цифры и этот файл меняются только при повторной оценке.

## Собственные полигоны (ключи свои, без подсказок организаторов)

`review/make_bench.py` берёт наш `runs/<глава>/layer.json`, выбирает 90 утверждений, портит 18 (20%) скриптом по категориям ТЗ и пишет `package.json` и `key.json` (`review/bench/<глава>/`). Портится только текст утверждения; испорченное слово или число обязательно есть в цитате автора, так что ошибка настоящая. Прогон: `uv run python -m review.run review/bench/<глава>/package.json -o ...`, оценка `score_review.py` своим ключом.

| Полигон | Ошибок (вес) | Найдено полностью / наполовину | Доля по весу | Ложных тревог | Из них на «верных, но неожиданных» |
|---|---|---|---|---|---|
| `barenblatt_par4` | 18 (41) | 16 / 0 | **90 %** | 3 | 0 |
| `baraboshkin_par1-2` | 18 (45) | 18 / 0 | **100 %** | 1 | 0 |

Состав ошибок: `barenblatt` — sign_flip 3, overgeneralization 3, lost_condition 2, wrong_scaling 2, measured_vs_inferred 8; `baraboshkin` — 5, 5, 0, 4, 4. «Верных, но неожиданных» только 4 и 1 вместо 10: в слоях мало утверждений, где абсолют или отрицание стоит и в тексте, и в цитате. Оговорка: порча шаблонная и близка к словарю проверки кодом, поэтому на реальных ошибках результат может быть хуже; решающими остаются модели.

### Правило отсева: проверено, не менялось

Условие: менять только если правило улучшает оба полигона и не снижает долю найденного. Проверено офлайн по `debug.json`:

| Правило | barenblatt (доля, ложных) | baraboshkin (доля, ложных) |

| как есть (потолок 20, ≥2 сигнала) | 90 %, 3 | 100 %, 1 |
| потолок 18 | 90 %, 2 | 96 %, 1 |
| потолок 16 | 85 %, 1 | 91 %, 0 |

Ни одно общее правило не улучшает оба полигона без потери доли (потолок 18 снижает долю на втором). Правило оставлено как есть. Замечание: ложные тревоги стоят в конце ранга, но резать по потолку дороже, чем они стоят.

## Проверка собственного курса (`review.self_check`)

`uv run python -m review.self_check runs/<глава> -o runs/<глава>/review_self.json` собирает пакет из `layer.json` и `video/*/spec.json` и прогоняет тот же модуль. В пакет входят: утверждения (`C…`), **тексты шагов** (`T…`: слои «Суть», «Как это работает», «Практика», «Нюансы», «Глубже» — их читает жюри, а они написаны моделью), аналогии (`A…`), фразы закадра (`L…`), факты сцены (`S…`), кадры, если ролик собран. У текстов шагов нет цитаты, поэтому они сверяются со всеми страницами узла (до четырёх). Потолок замечаний здесь `--max 60` (для тестового пакета в ~90 целей — 20).

`runs/latyshova_gl5_par17-20`: 330 утверждений + 200 текстов шагов + 42 аналогии + 13 фраз закадра + 16 фактов сцены (≈600 целей). Результат: 29 замечаний (27 к текстам шагов, 1 аналогия, 1 факт сцены), файл `runs/latyshova_gl5_par17-20/review_self.json`. Время 237 с (8 потоков), стоимость ≈ $0.86.

Оговорки (важно для чтения результата):
- Ключа к нашему курсу нет: замечания нужно проверять вручную по страницам.
- Проход `bulk` недетерминирован: на пограничных целях при разных запусках отмечаются разные, поэтому один прогон не гарантирует полноту. Проверено на 8 целях, найденных ранее: при `effort=low` отмечена C100, при `medium` — C178, закономерности нет; настройки не менялись.
- Часть замечаний к текстам шагов — про отрицательные утверждения вида «в главе нет …» (T074, T150, T182, T199): по страницам узла проверить их нельзя до конца, нужен взгляд человека.

## Четыре риска перед заморозкой

### 1. Полигон со всеми типами элементов (`make_bench.py --mixed`)

Пакет в пропорции контрольного пакета организаторов: 60 утверждений, 5 аналогий, 10 строк сценария, 6 фактов сцены (81 элемент), ≈20% испорчено в каждом типе. Аналогии — `it_analogy` из `layer.json`, строки сценария — `beats[].say`, факты сцены — из `spec.json` (инварианты, слои, плашка, допущения). Порча: утверждения и строки — по категориям ТЗ шаблонами; аналогии — граница заменена на «аналогия точная, для любых»; факты сцены — направление оси глубины или число ×10. Нужны главы со сценариями: `basniev_gl23-24`, `kuznetsov_gl10`, `latyshova_gl5_par17-20` (у `barenblatt` и `baraboshkin` в `runs/` нет `spec.json`). Подсчёт по типам: `review/bench_score.py`.

| Тип | Ошибок | Полностью | Наполовину | Доля по весу | Ложных тревог |
|---|---|---|---|---|---|
| утверждения | 36 | 33 | 0 | 93 % | 0 |
| аналогии | 3 | 2 | 1 | 83 % | 1 |
| строки сценария | 6 | 5 | 0 | 83 % | 1 |
| факты сцены | 2 | 1 | 0 | 50 % | 0 |
| **все типы** | 47 | 41 | 1 | **90 %** | **2** |

По главам: `basniev_gl23-24` 85 % (ложных 0), `kuznetsov_gl10` 100 % (2), `latyshova_gl5_par17-20` 84 % (0). Время ≈40–55 с на пакет из 81 элемента. Малые типы дают мало наблюдений (аналогий 3, фактов сцены 2): их цифры грубые.

Находка по ходу: первый прогон дал 85 %, часть находок засчитывалась наполовину, потому что модель ссылалась на соседнюю страницу (тоже подтверждающую исправление), а ключ ждёт страницу опорного утверждения. По README организаторов для фактов сцены и кадров верна «страница утверждения, которое иллюстрирует ролик». Поэтому в `review/run.py` страница замечания теперь привязывается к опорному утверждению (`anchor_page`): утверждение — своя проверенная цитата, строка сценария — `claim_ref`, аналогия и факт сцены — страница утверждения того же узла. Пороги не менялись. Остальные полигоны после правки без изменений (90 %/2 и 100 %/1).

### 2. Тонкая порча моделью (`make_bench.py --subtle`)

Ошибку вносит модель (`glava/llm.py`, tier `bulk`) как минимальную замену фрагмента; код механически проверяет, что исходный фрагмент дословно есть в пересказе и в цитате автора, а заменённого в цитате нет. Слова-маркеры («всегда», «любой» и т. п.) и простые антонимы модели запрещены.

| Полигон | Ошибок (вес) | Найдено полностью | Доля по весу | Ложных тревог |
|---|---|---|---|---|
| `subtle_barenblatt_par4` | 18 (44) | 8 | **45 %** | 0 |
| `subtle_baraboshkin_par1-2` | 18 (44) | 10 | **59 %** | 3 |

Это заметно хуже шаблонной порчи (90–100 %), и это честная оценка. По категориям (оба полигона вместе, найдено / всего): `wrong_scaling` 6/7, `measured_vs_inferred` 2/2, `overgeneralization` 5/10, `sign_flip` 4/9, **`lost_condition` 1/8**. Главная слабость — потерянные условия и тонкий переворот зависимости. Оговорка о ключе: у части порч фрагмент мелкий (7 из 36 — символы формул вроде «t» → «»), проверка кода гарантирует отличие от цитаты, но не то, что замена существенно меняет смысл; найдено 4 из 7 таких и 14 из 29 содержательных, так что на результат это сильно не влияет. Пороги не менялись.

### 3. Незнакомый материал

Модуль не видел `basniev_gl23-24` и `kuznetsov_gl10` (гидромеханика и литология, другие книги): ничего не падает, доля 85 % и 100 % (см. п. 1). Английский проверен только синтетическим пакетом из 5 элементов (см. выше) и словарём/промптами без привязки к русскому. **Реальной английской главы и Кузнецова стр. 150–162 в `runs/` нет** — нужен прогон конвейера на них (запрошено у Лида); домен «бурение» тоже не проверялся.

### 4. Устойчивость (`review/test_robust.py`)

`uv run python -m review.test_robust` — 13 тестов без сети и без денег (модель подменена): пустые и отсутствующие поля (`text`, `quote`, `page_pdf`, `id`, неизвестные типы, мусор вместо элементов), пустой и нечитаемый пакет, нет главы, пустой файл главы, ошибка API, исчерпанный бюджет, нет ключа, мусор в ответе модели, частичные сбои, огромный текст, пакет из 300 элементов, дедлайн. Ответ всегда проходит `review_output.schema.json`; при недоступной модели — ответ по проверкам кодом; код возврата 0.

Что сделано в `review/run.py`: нормализация пакета; очистка замечаний под схему (категория, тяжесть, страница, поля-строки); каждая запись проверяется схемой отдельно; запасной ответ при любом исключении; дедлайн 540 с на вызовы модели (`--deadline-s`), после него процесс завершается, даже если запросы API зависли; число рабочих уровней модели определяет, сколько сигналов требуется (код + bulk + strong → 2, один код → только проверки кодом). Время на 300 элементов: реального прогона нет; для оценки — самопроверка Латышовой на ≈600 целях при 8 потоках заняла 237 с.
